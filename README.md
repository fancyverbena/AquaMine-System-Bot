# AquaMine System Bot v2

Discord サーバー運営のための Bot です。ルール同意による認証、サポートチケット、レベリング（XP/レベル/ランキング）を1つにまとめました。

> ⚠️ **v1 との互換性はありません。** 設定・データの保存形式が変わったため、v1 の設定ファイルや DB は引き継げません。導入後は `/setup` から初期設定をやり直してください。

## 特徴

- **初期設定は `/setup` だけ** — ロールやチャンネルはセレクトメニューで選ぶだけ。ID のコピペやコマンド引数での設定は不要です
- **認証** — ルールパネルの「同意する」ボタンで認証ロールを付与。認証ログも残せます
- **チケット** — 種類を選んで件名と詳細を書くだけで専用チャンネルを作成。担当アサイン、メンバー追加/削除、無発言時の自動クローズ対応
- **レベリング** — 発言や VC 滞在で XP が貯まり、レベルアップ通知とレベル別ロール付与、進捗バー付きの `/rank`、ページ送りできる `/leaderboard`。XP の入手量やクールダウンはサーバーごとに調整でき、連投スパム対策も入っています
- **自動モデレーション** — NGワード・スパム・メンション乱用・招待リンクを検知し、違反回数に応じて警告→タイムアウト→キック→BAN と段階的に自動処罰（既定は無効、設定してから有効化）
- **抽選** — ボタンで参加するプレゼント企画。締切になると自動で抽選・発表し、Bot が落ちていた間の締切分も再起動後に処理されます
- **フィードバック** — `/suggest` の提案箱（👍👎 投票ボタン付き）と `/bugreport` のバグ報告。管理者はボタンで採用/見送り・対応中/完了などのステータスを管理できます
- **データは1ファイル** — 設定・XP・チケット・違反履歴・抽選・フィードバックはすべて SQLite の `data/bot.db` に保存

## 必要環境

- Python 3.12（Docker を使う場合は不要）
- Discord Developer Portal で **Server Members Intent** と **Message Content Intent** を有効化した Bot
  （Privileged Gateway Intents の SERVER MEMBERS INTENT と MESSAGE CONTENT INTENT を ON にしてください。
  MESSAGE CONTENT INTENT が OFF のままだと Bot がログインできません）

## 導入手順

### Docker（推奨）

1. `.env.sample` を `.env` にコピーし、`DISCORD_TOKEN` を設定します。
   テスト用サーバーですぐにコマンドを反映したい場合は `GUILD_ID` にそのサーバーの ID を入れます（任意）。
2. 起動します。

   ```bash
   docker compose up -d
   ```

   ※ 非 root ユーザーで動作します。ホスト側の `config/` `data/` の所有者と合わない場合は、書き込み権限を調整してください。

### Docker を使わない場合

```bash
pip install -r requirements.txt
python bot.py
```

## 初期設定（/setup）

Bot をサーバーに入れたら、管理者が任意のチャンネルで `/setup` を実行します。

1. パネルのチェックリストで未設定の項目を確認
2. セレクトメニューで **認証ロール**、**サポートロール**、**チケットカテゴリ**、**ログチャンネル** を選ぶ
3. 「レベル通知chにここを設定」で、そのチャンネルをレベルアップ通知先に
4. 「自動クローズ設定」で、無発言チケットを自動で閉じるまでの時間を設定（既定48時間、0で無効）
5. パネルを置きたいチャンネルで `/setup` を実行し直し、「認証パネルを設置」「チケットパネルを設置」を押す

現在の設定は `/settings` でいつでも確認できます。

チケットの作成はコマンドではなく、チケットパネルのセレクトメニューから行います。

## チケットの流れ

1. メンバーがパネルで種類（質問・相談 / 通報 / ホワイトリスト申請 / その他）を選ぶ
2. 件名と詳細を入力すると、カテゴリ内に専用チャンネルが作られます（1人1件まで）
3. スタッフは「担当する」ボタンか `/ticket assign` で担当を表明
4. 「閉じる」ボタンで閉鎖。会話記録（トランスクリプト）は `data/transcripts/` に保存され、ログチャンネルにも送られます
5. 無発言が自動クローズ時間を超えたチケットは、記録を残したうえで自動的に閉じられます

## レベリング

- 発言すると XP が貯まります（既定では1回 10〜25 XP、30秒に1回まで）
- 入手量などはサーバーごとに変更できます（再起動不要で即反映）。現在の値は `/settings` で確認できます
- `/rank 画像:True` で、レベル・順位・進捗をカード画像（PNG）で表示できます。画像生成には Pillow と日本語フォントを使います（Docker イメージには fonts-noto-cjk-core を同梱済み）。生成に失敗した場合は通常の埋め込み表示に自動で切り替わります

| 項目 | 既定値 | 変更範囲 | コマンド |
| --- | --- | --- | --- |
| XP入手量（最小〜最大） | 10〜25 | 0〜10000（最小 ≦ 最大） | `/level config xp_min: xp_max:` |
| クールダウン（秒） | 30 | 0〜3600 | `/level config cooldown_seconds:` |
| 最小文字数 | 3 | 0〜200 | `/level config min_length:` |
| VC XP（1分ごと） | 2 | 0〜1000（0で無効） | `/level config vc_xp_per_minute:` |

### VC（ボイスチャンネル）でも XP が貯まる

ボイスチャンネルに滞在すると、発言と同じレベルシステムに1分ごとに XP が付きます（既定 2 XP/分、`/level config vc_xp_per_minute:` で変更、0 で無効）。

- 対象になるのは、Bot でないメンバーが2人以上いるチャンネルで、AFK チャンネル以外にいる間だけです
- スピーカーミュート中（聞き専状態）は付きません。マイクミュートは付きます
- 60秒間対象の状態が続くごとに1分分を付与します。途中で対象でなくなったら、その分の経過時間は切り捨てられます（1分未満の端数は持ち越しません）
- Bot の再起動をまたいだ滞在時間は数えません。再起動時点で VC にいる人は、再起動後から新たに計測が始まります
- VC でレベルアップした場合、通知はレベル通知チャンネルに送られます（未設定の場合は通知されませんが、レベルロールの付与は行われます）
- VC の付与は、発言側のクールダウンや繰り返し判定の履歴には影響しません

### スパム対策

次の発言には XP が付きません（ブロックされた発言でタイマーや履歴が更新されることもありません）。

- **クールダウン中** — 前回 XP が付いてからクールダウン秒数が経っていない
- **テキストなし** — スタンプ・添付ファイルのみなど、本文が空の発言
- **短すぎる** — 本文が最小文字数に満たない発言
- **繰り返し** — 直近5件の「XPが付いた発言」のどれかと同一内容の発言。本文は空白の畳み込みと小文字化をしてから比較するので、間に別の発言を挟んでも、時間を空けても、別チャンネルでも弾かれます（履歴から外れた古い内容は再度カウントされます）

## 自動モデレーション（自動処罰）

荒らしやスパムを自動で検知し、段階的に処罰します。**既定では無効** なので、先に設定を済ませてから有効化してください。

### 検知するもの

- **NGワード** — 登録したワードを含む発言（空白の畳み込みと小文字化をしてから判定するので、大文字や余分な空白での回避はできません）。未登録のうちはデフォルトのセット（死ね、タヒ、fuck、bitch、nigger、nigga、faggot、free nitro、無料nitro、無料ニトロ、nitro無料、ニトロ無料）が使われ、`/automod ngword-add` / `ngword-remove` で編集した時点でその内容がサーバーのリストとして保存されます
- **スパム** — 10秒に5件以上の連投、または60秒以内に同一内容を3回以上送信
- **メンション乱用** — 1件の発言にユーザー+ロールのメンションがしきい値（既定5件）以上
- **招待リンク** — `discord.gg/`、`discord.com/invite/`、`discordapp.com/invite/` を含む発言（`/automod invites` で無効化可能）

管理者・メッセージ管理権限を持つメンバー・サーバーオーナーは処罰されません。`/automod exempt-channel` で対象外にしたチャンネルでも検知しません。`/automod ad-channel` で宣伝許可にしたチャンネルでは招待リンクだけ検知されません（NGワード・スパム・メンションは検知します）。

### 処罰の段階

違反した発言は削除され、違反履歴に記録されます。直近30日の違反回数（今回を含む）で処罰が重くなります。

| 違反回数 | 処罰 |
| --- | --- |
| 1〜10回目 | 警告（DMとログで通知）のみで許容 |
| 11回目 | タイムアウト10分 |
| 12回目 | キック |
| 13回目以降 | BAN（過去の発言は削除しません） |

1回の連投で何段も進まないよう、違反を記録してから60秒間は追加で記録しません（発言の削除だけ行います）。Bot より上位のロールを持つメンバーなど処罰できない場合は、失敗した旨がログに残ります。

### 有効化の手順

1. `/automod log-channel` で処罰ログの送信先を設定
2. `/automod ngword-add` で NG ワードを登録（必要な場合）
3. `/automod status` で設定を確認
4. `/automod toggle` で有効化

メンバーの違反履歴は `/automod history` で確認でき、`/automod reset` でリセットできます。

> スパム判定のバッファはメモリ上にだけあるため、Bot を再起動するとリセットされます。違反履歴は DB に保存され、再起動しても30日間のエスカレーションは継続します。

## ロールパネル（セルフ付与ロール）

メンバーがボタンで自分にロールを付け外しできるパネルです。お知らせ受け取り用ロールや色ロールなどに使えます。

### 設定の手順

1. `/roles add` でパネルに並べたいロールを追加（最大20件、並び順 = 追加順）
2. 必要なら `/roles exclusive` で排他モードを有効化
3. `/roles panel` でパネルを投稿（投稿先チャンネルを指定可能）

### 動作

- ボタンを押すと、そのロールを持っていなければ付き、持っていれば外れます。結果は押した本人にだけ見える形で返ります
- **排他モード**が有効なときは、パネルのロールを付けると他のパネルロールが自動で外れます（色ロールのように「どれか1つだけ」の用途向け）。パネル外のロールには影響しません
- ボタンは Bot を再起動してもそのまま使えます。パネルは何度でも貼り直せて、古いパネルのボタンも生き続けます
- パネルは投稿時点の設定で作られるため、ロールを追加・削除したら `/roles panel` で貼り直してください。設定から外したロールの古いボタンは、押しても「使えなくなりました」と返るだけで、ロールは付きません
- `/roles remove` で設定から外しても、すでにそのロールを持っているメンバーからは外れません
- @everyone・連携/Bot 管理ロール・Bot より上位のロールは追加できません

## 抽選（プレゼント企画）

ボタンで参加できる抽選（プレゼント企画）です。

### 開始のしかた

```
/giveaway start prize:ダイヤ装備一式 winners:3 duration:24h
```

- `prize` — 賞品（200文字まで）
- `winners` — 当選者数（1〜20人）
- `duration` — 期間。`30s`（秒）`10m`（分）`2h`（時間）`1d`（日）のように指定します（`24h` のような書き方も可）。有効範囲は10秒〜30日です

コマンドを実行したチャンネルに、参加ボタン付きのパネルが投稿されます。

### 動作

- メンバーは「🎉 参加する」ボタンを押して参加します。もう一度押すと参加を取り消せます。参加人数はパネルにその場で反映されます（Bot は参加できません）
- 締切になると自動で抽選され、パネルが終了表示に切り替わり、同じチャンネルに当選者がメンション付きで発表されます
- 抽選と参加者は DB に保存されるため、**Bot を再起動しても継続**します。Bot が落ちていた間に締切を迎えた抽選も、再起動直後に自動で終了処理されます
- 参加者がいなかった場合は「当選者なし」になります。参加者が当選者数より少ない場合は、参加者全員が当選します
- `/giveaway end` で締切前にすぐ終了することもできます。`/giveaway cancel` は抽選せずに中止します。開催中の一覧は `/giveaway list` で確認できます

### 再抽選

当選者が辞退した場合などは `/giveaway reroll` で再抽選できます。再抽選では**過去に当選した人全員が対象から外れ**、新しい当選者だけが発表されます。再抽選を繰り返しても、一度当選した人が再び当選することはありません。まだ当選していない参加者がいなくなると、再抽選はできません。

## フィードバック（提案箱・バグ報告）

メンバーからの提案とバグ報告を受け付ける仕組みです。投稿は専用チャンネルに転送され、提案には投票ボタン、どちらにも管理者用のステータスボタンが付きます。

### 設定の手順

1. `/feedback suggest-channel` で提案の投稿先チャンネルを設定
2. `/feedback bug-channel` でバグ報告の投稿先チャンネルを設定
3. 設定は `/settings` でも確認できます

投稿先が未設定のうちは、メンバーが `/suggest` `/bugreport` を使ってもエラーが返ります。

### 投稿のしかた

- `/suggest` — モーダルで提案内容（1000文字まで）を入力すると、提案チャンネルに「💡 提案 #番号」として投稿されます
- `/bugreport` — モーダルでタイトル（100文字まで）と内容（1500文字まで）を入力すると、バグチャンネルに「🐛 バグ報告 #番号」として投稿されます。再現手順・期待した動作・実際の動作を書いてもらうと対応が早くなります

### 投票（提案のみ）

- 投稿には 👍 と 👎 のボタンが付き、押すたびにその場で件数が更新されます
- 1人1票です。同じボタンをもう一度押すと取り消し、反対側を押すと切り替えになります
- 投稿者本人も自分の提案に投票できます
- 提案が「採用」か「見送り」になると投票は締め切られ、ボタンは無効化されます

### ステータス管理（管理者のみ）

投稿の下のボタンでステータスを変更できます。押せるのは管理者だけです（それ以外の人が押すとエラーが返ります）。変更すると Embed の色とステータス表示がその場で更新されます。

- 提案: 検討中 → **採用** / **見送り**
- バグ: 未対応 → **対応中** → **完了** / **見送り**（未対応から直接 完了・見送りも可）
- 採用・完了・見送りは終端状態で、それ以降はステータスを変更できません（対応中はまだ変更できます）

投稿と投票は DB に保存され、ボタンは Bot を再起動してもそのまま使えます。最近の投稿とステータスは `/feedback list`（種類で絞り込み可）で確認できます。

## Bump リマインダー（DISBOARD）

DISBOARD の `/bump` が成功すると、次の bump ができるようになるまで2時間かかります。この Bot は DISBOARD の成功メッセージを検知して時刻を覚えておき、2時間後に同じチャンネルへ「⏰ /bump できる時間になったよ！」と通知します。

### 動作

- 既定で有効です。DISBOARD の成功メッセージを見たときだけ予約する受動的な仕組みで、それ以外のときは何もしません
- 予約は1サーバーにつき1件だけです。新しく bump されると予約はリセットされます
- 通知先は bump が行われたチャンネルです。通知ロール（`/bump role`）が設定されていればそのロールを、なければ bump した人をメンションします（どちらも分からなければメンションなし）
- 予約は DB に保存されるため、Bot を再起動しても消えません。再起動中に時刻を迎えた予約は、起動直後に通知されます
- 動作確認は `/bump test` でできます（1分後にテスト通知が届きます。本物の予約がある場合は上書きされます）

### 注意

- 成功判定は DISBOARD のメッセージ文言（「表示順をアップ」など）への部分一致で行っています。DISBOARD 側の文言が変わると検知できなくなる可能性があります
- 他 Bot のメッセージ（Embed）を読むため、MESSAGE CONTENT INTENT が必要です（この Bot では有効化が必須になっています）

無効化したい場合は `/bump toggle` で切り替えてください（予約済みの通知はそのまま届きます）。

## データと設定ファイル

- `data/bot.db` — 設定・XP・チケット・違反履歴・抽選・フィードバック・Bump予約の全データ（SQLite）
- `data/transcripts/` — 閉鎖したチケットの会話記録
- `config/rules.json` — ルールパネルの本文（タイトル・説明・色・項目・フッター）。編集すると次にパネルを表示したときから反映されます

バックアップは `data/` フォルダごと取るのが簡単です。
