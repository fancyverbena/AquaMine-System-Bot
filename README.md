# AquaMine System Bot v2

Discord サーバー運営のための Bot です。ルール同意による認証、サポートチケット、レベリング（XP/レベル/ランキング）を1つにまとめました。

> ⚠️ **v1 との互換性はありません。** 設定・データの保存形式が変わったため、v1 の設定ファイルや DB は引き継げません。導入後は `/setup` から初期設定をやり直してください。

## 特徴

- **初期設定は `/setup` だけ** — ロールやチャンネルはセレクトメニューで選ぶだけ。ID のコピペやコマンド引数での設定は不要です
- **認証** — ルールパネルの「同意する」ボタンで認証ロールを付与。認証ログも残せます
- **チケット** — 種類を選んで件名と詳細を書くだけで専用チャンネルを作成。担当アサイン、メンバー追加/削除、無発言時の自動クローズ対応
- **レベリング** — 発言で XP が貯まり、レベルアップ通知とレベル別ロール付与、進捗バー付きの `/rank`、ページ送りできる `/leaderboard`。XP の入手量やクールダウンはサーバーごとに調整でき、連投スパム対策も入っています
- **データは1ファイル** — 設定・XP・チケットはすべて SQLite の `data/bot.db` に保存

## 必要環境

- Python 3.12（Docker を使う場合は不要）
- Discord Developer Portal で **Server Members Intent** を有効化した Bot
  （Privileged Gateway Intents の SERVER MEMBERS INTENT を ON にしてください。MESSAGE CONTENT INTENT は不要です）

## 導入手順

### Docker（推奨）

1. `.env.sample` を `.env` にコピーし、`DISCORD_TOKEN` を設定します。
   テスト用サーバーですぐにコマンドを反映したい場合は `GUILD_ID` にそのサーバーの ID を入れます（任意）。
2. 起動します。

   ```bash
   docker compose up -d
   ```

   ※ 非 root ユーザーで動作します。ホスト側の `config/` `data/` の所有者と合わない場合は、書き込み権限を調整してください。

### Docker を使わない場合

```bash
pip install -r requirements.txt
python bot.py
```

## 初期設定（/setup）

Bot をサーバーに入れたら、管理者が任意のチャンネルで `/setup` を実行します。

1. パネルのチェックリストで未設定の項目を確認
2. セレクトメニューで **認証ロール**、**サポートロール**、**チケットカテゴリ**、**ログチャンネル** を選ぶ
3. 「レベル通知chにここを設定」で、そのチャンネルをレベルアップ通知先に
4. 「自動クローズ設定」で、無発言チケットを自動で閉じるまでの時間を設定（既定48時間、0で無効）
5. パネルを置きたいチャンネルで `/setup` を実行し直し、「認証パネルを設置」「チケットパネルを設置」を押す

現在の設定は `/settings` でいつでも確認できます。

## コマンド一覧

| コマンド | 対象 | 内容 |
| --- | --- | --- |
| `/setup` | 管理者 | 設定パネルを開く |
| `/settings` | 管理者 | 現在の設定を表示 |
| `/help` | 全員 | 使い方（権限に応じて表示が変わります） |
| `/rank` | 全員 | 自分のレベル・順位・進捗を表示 |
| `/leaderboard` | 全員 | XP ランキング（10件ずつページ送り） |
| `/ticket assign` | スタッフ | チケットの担当者を設定 |
| `/ticket add` | 作成者/スタッフ | メンバーをチケットに追加 |
| `/ticket remove` | 作成者/スタッフ | メンバーをチケットから外す |
| `/level set-role` | 管理者 | レベル到達で付与するロールを設定 |
| `/level remove-role` | 管理者 | レベルロールの設定を解除 |
| `/level give-xp` | 管理者 | メンバーの XP を増減 |
| `/level reset` | 管理者 | メンバーの XP をリセット |
| `/level config` | 管理者 | XP入手量・クールダウン・最小文字数を変更（指定した項目だけ更新） |

チケットの作成はコマンドではなく、チケットパネルのセレクトメニューから行います。

## チケットの流れ

1. メンバーがパネルで種類（質問・相談 / 通報 / ホワイトリスト申請 / その他）を選ぶ
2. 件名と詳細を入力すると、カテゴリ内に専用チャンネルが作られます（1人1件まで）
3. スタッフは「担当する」ボタンか `/ticket assign` で担当を表明
4. 「閉じる」ボタンで閉鎖。会話記録（トランスクリプト）は `data/transcripts/` に保存され、ログチャンネルにも送られます
5. 無発言が自動クローズ時間を超えたチケットは、記録を残したうえで自動的に閉じられます

## レベリング

- 発言すると XP が貯まります（既定では1回 10〜25 XP、30秒に1回まで）
- 入手量などはサーバーごとに変更できます（再起動不要で即反映）。現在の値は `/settings` で確認できます

| 項目 | 既定値 | 変更範囲 | コマンド |
| --- | --- | --- | --- |
| XP入手量（最小〜最大） | 10〜25 | 0〜10000（最小 ≦ 最大） | `/level config xp_min: xp_max:` |
| クールダウン（秒） | 30 | 0〜3600 | `/level config cooldown_seconds:` |
| 最小文字数 | 3 | 0〜200 | `/level config min_length:` |

### スパム対策

次の発言には XP が付きません（ブロックされた発言でタイマーや履歴が更新されることもありません）。

- **クールダウン中** — 前回 XP が付いてからクールダウン秒数が経っていない
- **テキストなし** — スタンプ・添付ファイルのみなど、本文が空の発言
- **短すぎる** — 本文が最小文字数に満たない発言
- **繰り返し** — 直近5件の「XPが付いた発言」のどれかと同一内容の発言。本文は空白の畳み込みと小文字化をしてから比較するので、間に別の発言を挟んでも、時間を空けても、別チャンネルでも弾かれます（履歴から外れた古い内容は再度カウントされます）

## データと設定ファイル

- `data/bot.db` — 設定・XP・チケットの全データ（SQLite）
- `data/transcripts/` — 閉鎖したチケットの会話記録
- `config/rules.json` — ルールパネルの本文（タイトル・説明・色・項目・フッター）。編集すると次にパネルを表示したときから反映されます

バックアップは `data/` フォルダごと取るのが簡単です。
